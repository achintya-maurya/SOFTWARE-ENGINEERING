\section*{Work Completed}

During this phase of the project, I prepared the Class Diagram and Component Diagram for the Smart City Civic Complaint and Management System. These diagrams represent the system's object-oriented structure and modular software architecture.

\subsection*{1. Class Diagram}

The Class Diagram was designed to represent the major classes, their attributes, methods, and relationships. The main classes include User, Citizen, DepartmentOfficer, FieldWorker, Administrator, Department, Complaint, Assignment, Evidence, StatusHistory, Notification, and Feedback.

Inheritance was used to represent the relationship between the User class and its specialized roles. Associations and multiplicities were defined to describe interactions between citizens, complaints, departments, officers, workers, and supporting records. The diagram also represents complaint submission, verification, worker assignment, progress tracking, evidence submission, and resolution feedback.

\subsection*{2. Component Diagram}

The Component Diagram was prepared to represent the system's major software modules and their dependencies. The architecture was organized into three layers: Presentation Layer, Application Layer, and Data Layer, with planned smart services represented separately.

The Presentation Layer contains the Citizen Interface, Officer Dashboard, Worker Dashboard, and Admin Dashboard. The Application Layer includes authentication and role management, complaint management, verification and worker assignment, work and resolution management, notification services, and reporting and administration. The Data Layer represents database access and the PostgreSQL database.

The diagram also illustrates the interactions between components, data-access dependencies, and the proposed integration of complaint classification and duplicate detection. These smart services are identified as planned enhancements.

\section*{Outcome}

Both diagrams were prepared in UML-based notation with the objective of improving the clarity of the system design. The Class Diagram describes the system's structural relationships, while the Component Diagram presents its modular architecture and communication paths. Together, they provide a clearer understanding of the proposed system's organization and functionality.
